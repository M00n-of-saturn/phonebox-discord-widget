# Threat model

Scope: the bridge (PC), `ctl`, the widget (PhoneBox iframe on the phone) and the installer.
Trust boundary: Discord → bridge → PhoneBox agent (`127.0.0.1:8765`) → phone. Everything that comes from Discord or
from the agent is treated as untrusted. Likelihood and impact are high, medium or low, after mitigation.

Command words, status values and test names are quoted as they appear in the code, which uses Spanish identifiers.

| Threat | Asset | Vector | Impact | Likelihood | Mitigation | Evidence |
|---|---|---|---|---|---|---|
| XSS through Discord names | Phone panel | A nickname or channel name containing HTML or control characters | Medium: code would run in an `sandbox="allow-scripts"` iframe with no access to the panel, but it could request shortcuts | Low | The bridge sanitizes names (`sanitizeName`: no control characters, 32 max); the widget validates everything with `parseVoiceState` and renders only with `textContent`; `innerHTML`, `eval` and similar are forbidden | `tests/widget/VoicePanel.test.ts` ("un nombre con HTML se muestra como texto literal"), `tests/widget/security.test.ts`, `tests/shared/VoiceState.test.ts`, `tests/fixtures/nombre-html.json` and a screenshot on the phone |
| Arbitrary command from the phone | PC | The widget calls `phonebox.run(id)` with another id, or text is sent to the socket | High if anything free-form could run | Low | The panel only runs ids of existing shortcuts; each shortcut calls `ctl` with a fixed word; the bridge accepts only `alternar-silencio`, `alternar-ensordecer` and `colgar`, in a single line of at most 64 bytes | `tests/shared/Command.test.ts`, `tests/bridge/ControlServer.test.ts` ("una orden desconocida recibe error", "una línea larga sin salto") |
| Another local user writes to the control socket | Voice call | Connecting to the Unix socket | Low: mute or hang up | Low | Socket in `$XDG_RUNTIME_DIR` (the user's 0700 directory) with 0600 permissions; no network ports | `tests/bridge/ControlServer.test.ts` ("modo 0600"), `controlSocketPath` |
| Secret or token on disk, in logs or in the repository | Client Secret, refresh token | Config files, `dist/`, logs, process arguments | High: access to the Discord application | Low | Secrets only in the keyring (KWallet) through `secret-tool`, passed via stdin; `config.json` holds no secrets; logs carry types and codes only; secret scan returns zero matches | `tests/bridge/SecretStore.test.ts`, `tests/bridge/TokenService.test.ts`, `tests/bridge/DiscordVoiceSource.test.ts` ("los registros no contienen el token, nombres ni ids"), secret scan from Task 7, step 5 of the plan (`docs/2026-11-15-voice-panel-plan.md`) |
| Stolen refresh token | Discord account (voice only) | Malware with access to the user's session | Medium: read and change voice state | Low | Minimal scopes (`rpc`, `rpc.voice.read`, `rpc.voice.write`); the token rotates on every use; it is revoked by removing the application's authorization in Discord | `src/bridge/setup.ts` (`SCOPES`), `TokenService.refresh` |
| Third parties' personal data on the phone or in screenshots | Other people's names | Phone screen, screenshots, repository | Low | Medium | Only what is displayed is sent; real ids are replaced by an opaque key salted randomly at each start; no avatars; tests and screenshots use fictional data | `tests/bridge/VoiceStateTracker.test.ts` ("la clave es opaca"), `tests/fixtures/` |
| Compromised dependency | PC | Malicious npm package | High | Low | No runtime dependencies; three dev dependencies with a lockfile; third-party install scripts do not run (`esbuild` without its script); `pnpm audit` | `package.json`, `pnpm-lock.yaml`, Task 10 closing gate |
| Another local process impersonating the Discord socket | Access token | A fake socket that receives `AUTHENTICATE` | Medium | Low | The socket is looked up only in `$XDG_RUNTIME_DIR` (private to the user), never in `/tmp` | `tests/bridge/RpcClient.test.ts` (`findDiscordSocket`) |
| Stale state shown as current | User decisions (believing they are muted) | Bridge crashed or stopped | Medium | Low | 15 s `ttl` in the agent, 5 s heartbeat, and the widget's own timer that shows "Sin conexión con la PC" (No connection to the PC) if `at` does not change for 15 s | `tests/widget/PhoneBoxClient.test.ts`, `tests/bridge/PhoneBoxPublisher.test.ts`, verification in Tasks 7 and 10 |
| Duplicate bridge or leftover socket | Commands | Two bridges at once, or a socket left behind after a crash | Low | Low | The old socket is replaced only if nobody is listening; with a live bridge, the second one exits; a path that is not a socket is never deleted | `tests/bridge/ControlServer.test.ts` |
| Installer breaks the PhoneBox configuration | Panel | Writing `/api/settings` | Medium | Low | Prior backup `config.json.pre-discord.bak`; writes use `X-Config-Version`; changes are pure, idempotent and reversible with `--uninstall` | `tests/scripts/phoneboxConfig.test.ts` |
